# Book 08 — ATS Recommendation Engine

**Version:** 1.0

# Purpose

The ATS Recommendation Engine transforms ATS analysis into structured, actionable recommendations that help improve Resume quality and ATS compatibility.

Unlike a Resume Optimization Engine, this module never rewrites Resume content.

Its responsibility is to identify improvement opportunities and provide prioritized recommendations based entirely on the intelligence generated by previous books.

Every recommendation must be evidence-backed, explainable, and deterministic.

---

# Objectives

The ATS Recommendation Engine is responsible for

- Identifying Resume gaps.
- Identifying missing Job Description requirements.
- Generating actionable recommendations.
- Prioritizing recommendations.
- Estimating score improvement.
- Producing Recommendation JSON.
- Publishing Recommendation APIs.

# Recommendation Philosophy

The Recommendation Engine answers one question.

> **"What improvements should the candidate make to increase the ATS score?"**

It never answers

> **"Rewrite the Resume."**

Recommendations identify opportunities.

Resume Intelligence decides how to implement them.

# Design Principles

## Evidence Driven

Every recommendation must reference supporting Evidence Objects.

Recommendations may never be generated without supporting evidence.

---

## Deterministic

The same Resume and Job Description must always produce the same recommendations.

---

## Explainable

Every recommendation must explain

- Why it exists.
- Which requirement is affected.
- Which Resume section is affected.
- Which evidence supports it.

---

## Prioritized

Recommendations must be ordered by expected impact.

Higher-value improvements appear first.

---

## Independent

Recommendations are independent.

Implementing one recommendation must not require implementing another.

---

## Truthful

Recommendations must never encourage candidates to fabricate experience, skills, certifications, or projects.

Only truthful improvements are permitted.

---

# Recommendation Rules

## Rule 1

Every recommendation must reference one or more Evidence Objects.

---

## Rule 2

Every recommendation must reference one or more Job Description requirements.

---

## Rule 3

Recommendations never modify Score JSON.

---

## Rule 4

Recommendations never modify Evidence JSON.

---

## Rule 5

Recommendations must be deterministic.

---

## Rule 6

Recommendations must be independently executable.

---

## Rule 7

Recommendations must never recommend false information.

# Recommendation Priority

Recommendations are categorized by business impact.

Priority Levels

- Critical
- High
- Medium
- Low

Priority is determined by

- Requirement importance
- Score impact
- Coverage impact
- ATS compatibility impact

---

# Recommendation Validation

Validate

- Duplicate recommendations
- Missing evidence
- Missing requirement references
- Invalid priorities
- Invalid score estimates
- Truthfulness violations

Return validation failures only.
